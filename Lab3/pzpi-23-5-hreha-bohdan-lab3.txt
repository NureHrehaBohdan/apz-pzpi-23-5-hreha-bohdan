2 ЗАВДАННЯ
     На цій лабораторній роботі потрібно розробити клієнтський веб-застосунок (фронтенд) для розподіленої системи. Веб-застосунок повинен забезпечувати адміністративне управління компонентами системи та взаємодіяти з бекенд-сервером через REST API. Для реалізації застосунку необхідно використовувати сучасні технології розробки веб-інтерфейсів. Звіт повинен містити опис прийнятих інженерних рішень, будову застосунку та його взаємодію з іншими частинами системи.
     Звіт повинен містити:
– UML діаграму прецедентів (Use Case Diagram);
– UML діаграму компонент (Component Diagram);
– UML діаграму діяльності (Activity Diagram);
– UML діаграму станів (State Diagram).


3 ОПИС ВИКОНАНОЇ РОБОТИ

     3.1 Опис прийнятих інженерних рішень
     
     Веб-застосунок «Admin Panel» є адміністративним клієнтом розподіленої системи SkiTracker, реалізованим як SPA (Single Page Application) на основі React 18 та Vite. Застосунок надає адміністратору централізований інтерфейс для управління сенсорами, маршрутами, погодними даними, аналітикою, користувацькими звітами та резервними копіями бази даних.
     Маршрутизація реалізована за допомогою React Router v6. Усі розділи, окрім сторінки входу, захищені компонентом ProtectedRoute, який перевіряє наявність JWT-токена в localStorage. За відсутності токена виконується автоматичне перенаправлення на /login. Завдяки цьому несанкціонований доступ до адміністративних розділів виключається на клієнтському рівні.
     Взаємодія з бекенд-сервером централізована через єдиний екземпляр axios із налаштованим request interceptor. Перехоплювач автоматично зчитує JWT-токен із localStorage та додає заголовок Authorization: Bearer до кожного HTTP-запиту. Це усуває необхідність вручну передавати токен у кожному виклику та спрощує подальшу зміну механізму авторизації.
     Для сторінки Weather реалізовано автоматичне оновлення даних кожні 5 секунд за допомогою setInterval. Сторінки Analytics та Reports оновлюються кожні 30 секунд. При розмонтуванні компонента інтервал очищується через функцію, яку повертає useEffect, що запобігає витокам пам'яті.
     Для відображення часових рядів погодних показників використовується бібліотека Recharts, яка забезпечує адаптивні графіки (LineChart, BarChart) з автоматичним масштабуванням осей. Звіти користувачів про інциденти на трасах відображаються як на табличному поданні, так і на інтерактивній карті, реалізованій за допомогою React-Leaflet та тайлового сервісу OpenStreetMap.
     Структура застосунку поділена на чотири шари: Routing (AppRouter, ProtectedRoute), Pages (окремі сторінки), Components (Layout, Sidebar, WeatherChart) та API Layer (модулі axios для кожного ресурсу). Такий підхід знижує зв'язність між модулями та полегшує підтримку і розширення функціональності.
     
     3.2 UML Діаграми
     
     UML-діаграма прецедентів (див. дод. Б.1) відображає функціональні можливості адміністративного веб-застосунку та акторів, що з ним взаємодіють.
     Основним актором є Адміністратор, який після авторизації отримує доступ до всіх розділів системи. Бекенд-сервер виступає зовнішнім актором, що обробляє REST-запити. Картографічний сервіс (OpenStreetMap) задіюється під час відображення звітів на карті.
     Діаграма охоплює основні прецеденти: авторизацію, перегляд дашборду, управління сенсорами (додавання і видалення), управління маршрутами (додавання, видалення, перегляд середньої швидкості), перегляд погодного дашборду та аналітики, перегляд користувацьких звітів у таблиці та на карті, а також управління резервними копіями (створення, відновлення, видалення).
     UML-діаграма компонентів (див. дод. Б.2) відображає внутрішню архітектуру застосунку та залежності між модулями. Routing Layer містить AppRouter та ProtectedRoute, що забезпечують навігацію та захист маршрутів. Pages Layer охоплює вісім окремих сторінок, кожна з яких відповідає за свій функціональний розділ. Components Layer включає спільні UI-компоненти: Layout, Sidebar та WeatherChart. API Layer містить вісім спеціалізованих модулів, які звертаються до бекенду через єдиний axios-екземпляр. Модуль tokenManager відповідає за зчитування та збереження JWT у localStorage.
     UML-діаграма діяльності (Activity Diagram) процесу автентифікації (див. дод. Б.3) показує послідовність дій при вході адміністратора в систему. Після відкриття застосунку перевіряється наявність токена. За його відсутності відображається форма входу. Після введення credentials та їх валідації надсилається POST-запит до /auth/login. При успішній відповіді JWT-токен зберігається в localStorage і відбувається перенаправлення на головну сторінку.
     UML-діаграма пакетів (Package Diagram) адміністративної панелі (див. дод. Б.4) відображає структуру клієнтської частини застосунку та взаємозв’язки між основними модулями системи. Проєкт поділено на логічні пакети: bootstrap, routes, pages, components, api, utils та assets. Пакет bootstrap відповідає за ініціалізацію застосунку та підключення маршрутизації, routes забезпечує навігацію та захищені маршрути, pages містить основні екрани інтерфейсу, components — перевикористовувані UI-компоненти, api реалізує взаємодію з backend через HTTP-запити, utils містить допоміжні утиліти, зокрема роботу з токеном автентифікації, а assets зберігає статичні ресурси. Зовнішні залежності включають React, React Router DOM, Axios та бібліотеки візуалізації й мапінгу. Діаграма демонструє ієрархічну структуру застосунку та основні залежності між його модулями.
     
     3.3 Приклади програмної реалізації
     
     Для централізованої обробки авторизаційних заголовків було налаштовано єдиний axios-екземпляр із request interceptor. Перехоплювач зчитує JWT-токен зі сховища та автоматично додає його до кожного запиту, завдяки чому усі модулі API-шару не потребують явної передачі токена.

01 import axios from "axios";
02 import { getToken } from "../utils/token";
03 
04 const api = axios.create({
05     baseURL: "http://localhost:8080",
06 });
07 
08 api.interceptors.request.use((config) => {
09     const token = getToken();
10     if (token) {
11         config.headers.Authorization = `Bearer ${token}`;
12     }
13     return config;
14 });
15 
16 export default api;
     
     Для захисту маршрутів від неавторизованого доступу реалізовано компонент ProtectedRoute. Він перевіряє наявність JWT-токена в localStorage і в разі його відсутності перенаправляє користувача на сторінку входу за допомогою компонента Navigate бібліотеки React Router.

01 import { Navigate } from "react-router-dom";
02 
03 export default function ProtectedRoute({ children }) {
04     const token = localStorage.getItem("token");
05 
06     if (!token) {
07         return <Navigate to="/login" />;
08     }
09 
10     return children;
11 }

     Для управління резервними копіями реалізовано три асинхронні обробники. Функція handleCreate ініціює POST-запит до /admin/backup та після отримання відповіді оновлює список копій. Функція handleRestore надсилає запит на відновлення конкретного знімка та сповіщає адміністратора про успіх. Функція handleDelete запитує підтвердження через window.confirm, а після його отримання виконує DELETE-запит і перезавантажує список.

01 const handleCreate = async () => {
02     try {
03         await createBackup();
04         await loadBackups();
05     } catch (e) { console.log(e); }
06 };
07 
08 const handleRestore = async (filename) => {
09     try {
10         await restoreBackup(filename);
11         alert("Restored successfully");
12     } catch (e) { console.log(e); }
13 };
14 
15 const handleDelete = async (filename) => {
16     const ok = window.confirm("Delete this backup?");
17     if (!ok) return;
18     try {
19         await deleteBackup(filename);
20         await loadBackups();
21     } catch (e) { console.log(e); }
22 };

4 ВИСНОВКИ

     У ході виконання лабораторної роботи було розроблено адміністративний веб-застосунок для системи SkiTracker. Реалізований SPA на основі React 18 та Vite забезпечує повноцінне управління сенсорами, маршрутами, погодними даними, аналітикою, користувацькими звітами та резервними копіями бази даних.
     Для захисту адміністративних розділів реалізовано компонент ProtectedRoute із перевіркою наявності JWT-токена. Взаємодія з бекенд-сервером централізована через єдиний axios-екземпляр із request interceptor, що автоматично додає заголовок авторизації до всіх HTTP-запитів.
     Для відображення даних у реальному часі на сторінках Weather та Analytics застосовано механізм автоматичного оновлення через setInterval. Бібліотеки Recharts та React-Leaflet забезпечили візуалізацію аналітичних графіків та інтерактивної карти звітів відповідно.
     У звіті побудовано UML-діаграми прецедентів, компонентів, діяльності та станів, які відображають функціональні можливості системи, її внутрішню архітектуру та логіку автентифікації і управління сесією.
