3 ОПИС ВИКОНАНОЇ РОБОТИ
     3.1 Загальні відомості про систему
     
     Назва системи: Twitch
     Розробник: Amazon
     Призначення системи:
     Twitch — це одна з найбільших у світі платформ для проведення прямих відеотрансляцій у режимі реального часу. Спочатку сервіс був орієнтований переважно на трансляції відеоігор та кіберспортивних турнірів, однак з часом функціональність платформи значно розширилася. Сьогодні Twitch використовується також для музичних трансляцій, творчих стрімів, навчальних ефірів, подкастів та звичайного спілкування з аудиторією.
     Основними користувачами системи є стрімери, які створюють контент, та глядачі, що переглядають трансляції й взаємодіють через чат. Крім цього, платформою користуються модератори, рекламодавці та адміністратори сервісу.
     Система забезпечує проведення прямих трансляцій, обробку відеопотоків, обмін повідомленнями у чаті в реальному часі, систему рекомендацій, підписки на канали, інтеграцію платежів та механізми модерації контенту. Через величезну кількість одночасних користувачів Twitch є прикладом високонавантаженої розподіленої програмної системи.
     
     3.2 Архітектурний стиль системи
     
     Архітектура Twitch побудована на поєднанні декількох сучасних архітектурних підходів. Основою системи є мікросервісна архітектура, доповнена клієнт-серверною моделлю та елементами подієво-орієнтованої взаємодії.
     Клієнт-серверний підхід використовується для взаємодії між користувацькими додатками та серверною інфраструктурою. Користувачі через браузер, мобільний додаток або Smart TV надсилають запити до серверів Twitch, отримують відеопотоки, повідомлення чату та інший контент.
     Мікросервісна архітектура дозволяє розділити систему на незалежні сервіси, кожен з яких виконує окрему функцію. Наприклад, один сервіс відповідає за авторизацію користувачів, інший — за обробку чатів, окремий сервіс працює з рекомендаціями, а ще один займається відеострімінгом. Такий підхід значно спрощує масштабування системи та дозволяє оновлювати окремі компоненти без зупинки всієї платформи.
     Подієво-орієнтована архітектура використовується для обробки великої кількості подій у реальному часі. До таких подій належать повідомлення чату, запуск трансляцій, підписки, донати та сповіщення. Для передачі подій між сервісами застосовуються брокери повідомлень та системи черг.
     Вибір саме такої архітектури пояснюється необхідністю підтримки мільйонів одночасних користувачів, високої швидкості обробки даних та мінімальних затримок під час трансляцій.
     
     3.3 Основні компоненти системи
     
     Інтерфейс користувача:
     Інтерфейс Twitch представлений вебверсією, мобільними додатками та клієнтами для Smart TV. Frontend відповідає за відображення відео, чатів, рекомендацій та інших елементів системи. Для створення інтерфейсу використовуються сучасні JavaScript-фреймворки та WebSocket-з’єднання для роботи чату у реальному часі.
     Серверна частина:
     Backend Twitch складається з великої кількості мікросервісів, кожен із яких виконує окрему функцію. Центральним елементом взаємодії є API Gateway, який маршрутизує запити користувачів до відповідних сервісів.
     
     
     Серверна частина включає:
* сервіс авторизації;
* сервіс чатів;
* сервіс стрімінгу;
* сервіс рекомендацій;
* сервіс платежів;
* систему модерації.
* Рівень бізнес-логіки
     На цьому рівні реалізується основна логіка роботи системи. Бізнес-логіка відповідає за:
* перевірку прав доступу;
* рекомендації контенту;
* управління підписками;
* обробку платежів;
* систему модерації;
* взаємодію між сервісами.
* Рівень зберігання даних
     Для зберігання інформації використовуються реляційні та NoSQL бази даних. Дані користувачів, підписок та платежів зберігаються у реляційних БД, тоді як чати, аналітика та великі обсяги неструктурованих даних можуть зберігатися у NoSQL-сховищах.
     Для кешування активно використовується Redis, який дозволяє швидко отримувати популярні дані та зменшувати навантаження на бази даних.
     Допоміжні сервіси:
     До допоміжних компонентів системи належать:
* CDN для доставки відео;
* системи логування;
* системи моніторингу;
* брокери повідомлень;
* балансувальники навантаження;
* аналітичні сервіси.
     CDN забезпечує швидку доставку відео користувачам із різних регіонів світу, а брокери повідомлень дозволяють ефективно передавати події між мікросервісами.
     
     3.4 Взаємодія компонентів
     
     Робота Twitch базується на постійному обміні даними між клієнтськими додатками, серверами та допоміжними сервісами. Коли стрімер запускає трансляцію, відеопотік передається через протокол RTMP на ingest-сервери. Далі відео обробляється сервісами транскодування, які створюють декілька варіантів якості потоку. 

Рисунок 3.1 — Архітектурна діаграми системи

     Після цього відео передається через CDN-мережу до глядачів. Завдяки цьому користувачі отримують потік із найближчого серверного вузла, що дозволяє зменшити затримки.
     Система чату працює окремо через WebSocket-з’єднання. Це дозволяє забезпечити миттєву доставку повідомлень між користувачами.
     Для взаємодії між мікросервісами використовуються REST API, gRPC та брокери повідомлень. Для передачі подій у реальному часі можуть використовуватися Kafka або Redis Pub/Sub.

     3.5 Масштабованість та надійність
     
     Механізми балансування навантаження
     Оскільки Twitch одночасно обслуговує мільйони користувачів, система потребує ефективного розподілу навантаження між великою кількістю серверів. Для цього використовуються балансувальники навантаження (Load Balancers), які автоматично перенаправляють запити користувачів на найменш завантажені сервери.
     Балансування відбувається на декількох рівнях. На рівні мережі CDN розподіляє відеотрафік між регіональними вузлами, щоб користувачі отримували потоки з найближчого дата-центру. На серверному рівні API-запити розподіляються між декількома екземплярами мікросервісів. Це дозволяє системі стабільно працювати навіть під час великих кіберспортивних трансляцій або пікових навантажень.
     Крім цього, система підтримує автоматичне масштабування серверів. Якщо навантаження збільшується, платформа може автоматично запускати нові екземпляри сервісів, а після зменшення навантаження — вимикати зайві.
     Відмовостійкість
     Для забезпечення безперервної роботи Twitch використовує механізми резервування та дублювання компонентів системи. Критично важливі сервіси мають декілька резервних копій, які працюють паралельно. Якщо один із серверів виходить з ладу, балансувальник автоматично перенаправляє трафік на інші доступні сервери.
     Важливу роль відіграють системи моніторингу та health-check перевірки. Вони постійно контролюють стан серверів, мікросервісів та мережевих з’єднань. У разі виявлення проблеми система автоматично ізолює несправний компонент і замінює його резервним.
     Для захисту від втрати даних Twitch використовує реплікацію баз даних між декількома дата-центрами. Це дозволяє зберігати працездатність навіть у випадку часткового збою інфраструктури або відмови окремого дата-центру.
     Кешування
     Через величезну кількість користувачів Twitch активно використовує кешування для зменшення навантаження на бази даних та прискорення роботи системи. Для цього переважно застосовується Redis — високопродуктивне in-memory сховище.
     У кеші можуть зберігатися:
* популярні стріми;
* інформація про користувачів;
* результати рекомендацій;
* сесії авторизації;
* повідомлення чатів;
* статистика переглядів.
     Завдяки кешуванню система може швидко обробляти запити без постійного звернення до основної бази даних. Це особливо важливо під час масових трансляцій, коли одночасно надходять сотні тисяч запитів.
     Також CDN фактично виконує роль глобального кешу для відеоконтенту. Відеопотоки зберігаються на регіональних серверах CDN, що значно скорочує затримки для користувачів.
     Реплікація
     Реплікація даних є важливою частиною архітектури Twitch. Бази даних мають декілька копій, розміщених у різних дата-центрах. Це дозволяє не лише підвищити надійність, але й розподіляти навантаження між серверами.
     Для читання даних можуть використовуватися replica-сервери, тоді як основний сервер відповідає за запис інформації. Такий підхід дозволяє значно підвищити продуктивність системи.
     Крім баз даних, реплікуються також відеодані та конфігурації сервісів. Якщо один із вузлів стає недоступним, система може швидко переключитися на резервну копію без значного впливу на користувачів.
     Контейнеризація та хмарна інфраструктура
     Для розгортання та управління мікросервісами Twitch використовує контейнеризацію. Docker-контейнери дозволяють запускати сервіси в ізольованому середовищі, що спрощує оновлення, тестування та масштабування системи.
     Оркестрація контейнерів виконується за допомогою Kubernetes. Kubernetes автоматично:
* розподіляє контейнери між серверами;
* контролює стан сервісів;
* перезапускає несправні компоненти;
* масштабує систему залежно від навантаження.
     Хмарна інфраструктура AWS забезпечує Twitch доступ до великої кількості обчислювальних ресурсів та дата-центрів по всьому світу. Використання хмарних технологій дозволяє платформі швидко адаптуватися до змін навантаження та забезпечувати стабільну роботу навіть під час глобальних подій або великих кіберспортивних турнірів.
     
     

4 ВИСНОВКИ
     
     У результаті виконання практичного заняття було досліджено архітектуру програмної системи Twitch та проаналізовано особливості її побудови як високонавантаженої розподіленої платформи для проведення відеотрансляцій у режимі реального часу.
     Під час роботи було визначено, що основою системи є мікросервісна архітектура у поєднанні з клієнт-серверним та подієво-орієнтованим підходами. Така архітектура дозволяє забезпечити високу масштабованість, відмовостійкість та ефективну обробку великої кількості одночасних користувачів і подій у реальному часі.
     Було проаналізовано взаємодію основних компонентів системи, зокрема клієнтських застосунків, API Gateway, сервісів авторизації, стрімінгу, чатів, рекомендацій та платіжної системи. Також розглянуто механізми доставки відеопотоків через CDN, використання брокерів повідомлень для асинхронної взаємодії сервісів та роль кешування за допомогою Redis.
     Окрему увагу приділено питанням масштабованості та надійності системи. Було досліджено механізми балансування навантаження, автоматичного масштабування, реплікації даних, контейнеризації та використання хмарної інфраструктури AWS. Встановлено, що саме поєднання цих технологій дозволяє Twitch підтримувати стабільну роботу навіть під час великих пікових навантажень.
     У ході виконання практичної роботи було оцінено переваги та обмеження обраних архітектурних рішень. До основних переваг належать гнучкість системи, можливість незалежного масштабування сервісів, висока доступність та ефективна обробка подій у реальному часі. Водночас мікросервісна архітектура ускладнює підтримку системи, моніторинг та координацію взаємодії між компонентами.
