1 Бізнес вимоги
1.1 Аналіз проблеми

     Гірськолижні курорти постійно стикаються з викликами у забезпеченні безпеки спортсменів та відпочиваючих. На даний момент контроль умов на склонах здійснюється переважно вручну з використанням застарілих методів моніторингу. Відсутня централізована система для отримання даних про погоду на різних висотах та відслідкування тренувань в реальному часі.
     Цей проект спрямований на створення інтегрованої IoT-системи, яка дозволить автоматизувати моніторинг безпеки та надати спортсменам необхідну інформацію для безпечного катання.

Загальні проблеми існуючих систем:
1. Відсутність комплексного підходу — жодна система не поєднує моніторинг погоди, управління маршрутами, відстеження тренувань та звіти безпеки.
2. Затримка інформації — більшість систем показують дані з годинною або більшою затримкою.
3. Низька взаємодія з користувачем — немає можливості отримувати фідбек від лижників у реальному часі.
Як нова система покращить ситуацію:
1. Комплексність: поєднує моніторинг погодних умов, управління маршрутами, відстеження тренувань лижників і формування звітів безпеки в одній платформі.
2. Реальний час: GPS та сенсори IoT дозволяють отримувати та обробляти дані у режимі реального часу.
3. Зворотній зв’язок: користувачі можуть повідомляти про небезпеки або стан трас через мобільний додаток.
4. Доступність: система побудована з використанням дешевих IoT- сенсорів та відкритих технологій, що знижує вартість впровадження.

2. Опис призначення та логіки системи
2.1 Опис призначення системи

     Призначення системи — стати платформою для управління безпекою на гірськолижних курортах, яка в реальному часі надає точну та актуальну інформацію про умови катання, допомагає операторам курортів приймати обґрунтовані рішення для забезпечення безпеки та оптимізації роботи. Система дозволяє користувачам фіксувати треки спусків, швидкість, відстань та інші показники. одночасно забезпечуючи безпечне та приємне перебування на курорті.
2.2 Опис бізнес-логіки

     Система повинна забезпечувати централізовану взаємодію між користувачами, IoT-пристроями та адміністраторами курорту. Основна бізнес-логіка побудована навколо принципу автоматичного аналізу та реагування на потенційні небезпеки.
     Бізнес-логіка також передбачає пріоритет безпеки над іншими функціями системи. 
Програмна система працюватиме згідно наступних бізнес процесів:
1. Моніторинг погодних умов
* Автоматичне збирання даних з датчиків на різних висотах;
* Аналітика в реальному часі (температура, вітер, видимість, осадки);
* Індикатор	рівня	безпеки	(GREEN/YELLOW/RED)	для	кожного маршруту.
2. Управління маршрутами
* Каталог маршрутів з різними рівнями складності;
* Детальна	інформація	про	маршрут	(довжина,	перепад	висоти, координати);
* Статус маршруту (відкритий/закритий/обережно).
3. Відслідкування тренувань
* Запуск та завершення тренування;
* Автоматичний	розрахунок	статистики	для	кожного	тренування (швидкість, дистанція, зміна висот);
* Особистий кабінет з історією тренувань.
4. Система репортів про безпеку
* Користувачі можуть повідомляти про виявлені небезпеки;
* Видимість репортів для інших користувачів.
5. Управління користувачами
* Реєстрація та автентифікація;
* Профіль користувача (email, аварійний контакт).
6. Адміністративна панель
* Управління датчиками та маршрутами;
* Перегляд статистики тренувань користувачів. Аналітика та звіти;
* Управління репортами про безпеку.

2.3 Адміністрування системи

      Для забезпечення стабільної роботи системи передбачена адміністративна панель, доступна лише авторизованим адміністраторам курорту.
      Адміністрування системи включає:
* додавання, редагування та видалення маршрутів;
* управління IoT-датчиками та перевірку їх статусу;
* моніторинг погодних показників у режимі реального часу;
* обробку та модерацію репортів про небезпеки;
* перегляд статистики активності користувачів;
* управління обліковими записами користувачів;
* формування звітів щодо безпеки та використання маршрутів;
* перегляд журналів подій та системних помилок.
      Адміністратор має можливість оперативно закривати маршрути, змінювати рівень небезпеки та надсилати сповіщення користувачам у випадку надзвичайних ситуацій.
      
      2.4 Інтернаціоналізація системи
      
      Система проектується з урахуванням можливості подальшого використання на міжнародних гірськолижних курортах.
      
      Для цього передбачено:
* підтримку декількох мов інтерфейсу;
* використання універсальних форматів дати, часу;
* можливість додавання нових мов без зміни програмного коду;
* підтримку різних часових поясів;
* адаптацію системи до регіональних особливостей курортів.
      Інтернаціоналізація дозволяє масштабувати систему для використання в різних країнах та забезпечує зручність роботи для іноземних користувачів.
      
      2.5 Локалізація системи
      
      Локалізація системи буде забезпечувати адаптацію інтерфейсу та функціональності відповідно до мови та регіону користувача.
      Система підтримуватиме:
* переклад інтерфейсу користувача;
* локалізовані повідомлення та сповіщення;
* використання локальних одиниць вимірювання;
* відображення валют, часу та форматів дат відповідно до регіону;
* автоматичне визначення мови користувача.
      Для українських користувачів основною мовою системи буде українська, а також планується підтримка англійської мови для іноземних туристів та міжнародних курортів.
      
      3 Scope and Limitations
      3.1 Scope of Initial Release
      
      Початковий реліз системи включає серверну частину, IoT-підсистему, Web-клієнт та мобільний додаток, які разом забезпечують моніторинг безпеки гірськолижного курорту та відстеження активності користувачів у режимі реального часу.
      3.1.1 Серверна частина та IoT
      Основні завдання серверної частини включають централізоване управління всіма даними системи та обробку бізнес-логіки. Сервер отримує дані від IoT-датчиків та зберігає їх у базі даних для подальшого аналізу. На основі погодних умов система автоматично розраховує поточний рівень безпеки кожного маршруту та визначає його статус (безпечний / обережний / небезпечний).
      Сервер також відповідає за:
* реєстрацію та автентифікацію користувачів;
* управління профілями користувачів;
* зберігання інформації про маршрути та їх характеристики;
* обробку тренувань і розрахунок статистики;
* збір та обробку репортів про небезпеки.
      Паролі користувачів зберігаються у захищеному вигляді із використанням алгоритмів хешування.
      IoT-підсистема представлена мережею датчиків, розміщених на різних висотах гірськолижного курорту. Датчики збирають інформацію про температуру, вологість, швидкість вітру, опади та видимість у режимі реального часу. Дані передаються на сервер кожні 30 секунд для подальшої обробки та аналізу.
      На етапі розробки використовується емулятор датчиків, який генерує реалістичні погодні дані без необхідності фізичного обладнання. Емулятор враховує залежність погодних умов від висоти, наприклад зниження температури або збільшення швидкості вітру на вершинах.
      3.1.2 Web-клієнт та мобільний клієнт
      Web-клієнт реалізований у вигляді адміністративної панелі для централізованого керування системою та моніторингу даних у режимі реального часу. Адміністратор може переглядати стан датчиків, активні тренування користувачів, репорти про небезпеки та погодні умови на маршрутах.
      Основні можливості Web-клієнта:
* управління маршрутами (створення, редагування, видалення);
* перегляд характеристик та статусу датчиків;
* робота з тренуваннями користувачів;
* аналіз та модерація репортів про небезпеки;
* перегляд статистики та аналітики системи.
      Мобільний клієнт орієнтований на спортсменів та відпочиваючих. Додаток забезпечує швидкий доступ до актуальної інформації про стан трас та дозволяє відслідковувати власну активність.
      Основна функціональність мобільного додатка:
* інтерактивна карта маршрутів із відображенням їхнього поточного стану;
* перегляд погодних умов та інформації про маршрути;
* запуск та завершення тренувань;
* історія тренувань у профілі користувача;
* створення репортів про небезпеки з автоматичним визначенням геолокації;
* сповіщення про зміни погодних умов або статусу маршрутів.
      Усі компоненти системи взаємодіють через серверну частину, що забезпечує синхронізацію даних у режимі реального часу та актуальність інформації для користувачів і адміністраторів системи.
      
      3.2 Scope of Subsequent Releases
      
      У майбутніх релізах планується інтеграція технологій штучного інтелекту для підвищення рівня безпеки, автоматизації аналізу даних та покращення користувацького досвіду.
      Штучний інтелект може використовуватися для:
* прогнозування небезпечних погодних умов;
* автоматичного визначення ризику лавин;
* рекомендації безпечних маршрутів для користувача;
* аналізу стилю катання спортсмена;
* виявлення аномальної поведінки або можливих травм;
* автоматичного аналізу репортів про небезпеку;
* персоналізованих рекомендацій тренувань.
      AI також може допомагати адміністраторам шляхом автоматичного формування попереджень та прогнозів на основі погодних даних і історичної статистики.
      Збирання даних
      Для навчання та роботи моделей система може збирати:
* погодні дані з IoT-сенсорів;
* GPS-треки користувачів;
* швидкість руху та перепади висот;
* історію тренувань;
* інформацію про небезпечні ділянки;
* репорти користувачів;
* статистику інцидентів;
* історичні погодні зміни.
      Дані збираються автоматично через IoT-пристрої та мобільний додаток користувача. Інформація анонімізується та зберігається у базі даних для подальшої аналітики.
      Навчання та використання моделей
      На початкових етапах доцільно використовувати готові AI API та попередньо навчені моделі для аналізу погодних умов і прогнозування ризиків.
      
      У майбутньому можливе:
* донавчання існуючих моделей на власних даних курорту;
* створення власних моделей прогнозування небезпек;
* використання ML-моделей для аналізу поведінки користувачів.
      Найбільш ефективним підходом є комбінування готових AI-рішень із поступовим накопиченням власного датасету для спеціалізованого навчання моделей під конкретні особливості гірськолижних курортів.
      
      3.3 Limitations and Exclusions
      
      Незважаючи на широкий функціонал системи, початковий реліз має ряд технічних та функціональних обмежень. Частина можливостей навмисно не включена до системи через складність реалізації, високу вартість впровадження або необхідність зосередитися на основних задачах моніторингу безпеки.
      Технічні та функціональні обмеження
      Система залежить від стабільного інтернет-з’єднання, оскільки передача даних від IoT-датчиків та синхронізація мобільного застосунку здійснюються у режимі реального часу. У випадку втрати мережі можливі затримки оновлення інформації або тимчасова недоступність окремих функцій.
      Точність оцінки безпеки маршрутів безпосередньо залежить від кількості та якості встановлених IoT-сенсорів. При недостатньому покритті курорту або несправності датчиків система може надавати менш точні результати аналізу погодних умов.
      GPS-відстеження тренувань може працювати нестабільно у складних погодних умовах, густому тумані або у місцях зі слабким сигналом супутникового зв’язку. Через це можливі похибки у визначенні маршруту, швидкості або дистанції користувача.
      
      AI-функціональність у майбутніх релізах також матиме певні обмеження. Прогнозування небезпечних ситуацій або аналіз поведінки користувачів не може гарантувати абсолютну точність, оскільки результати залежать від якості накопичених даних та умов навчання моделей.
      Крім того, система не розрахована на повністю автономне прийняття критичних рішень. Остаточне рішення щодо закриття маршрутів або реагування на надзвичайні ситуації залишається за адміністраторами курорту.
      Навмисно виключений функціонал
      У межах початкового релізу навмисно не реалізовуються наступні можливості:
      інтеграція з платіжними системами та онлайн-бронюванням послуг курорту;
* бронювання готелів, підйомників або оренди спорядження;
* соціальна мережа для користувачів із чатами та публікаціями;
* відеострімінг із трас або камер спостереження;
* підтримка розумних wearable-пристроїв, таких як смарт-годинники чи фітнес-браслети;
* автоматичний виклик рятувальних служб без підтвердження адміністратора;
* використання дронів або роботизованих систем моніторингу.
      Даний функціонал виключений через необхідність зосередитися на ключовій меті системи — забезпеченні моніторингу погодних умов, контролю безпеки маршрутів та відстеженні активності користувачів. Також реалізація окремих можливостей потребує значних фінансових витрат, складнішої інфраструктури або додаткових юридичних та безпекових вимог.
	
4.3 Опис програмних засобів та інструментів

     Для розробки системи буде використовуватися надійний технологічний стек, орієнтований на стабільність, масштабованість та простоту підтримки. Основою серверної частини стане Java Spring Boot, який забезпечує чітку архітектуру, високу продуктивність та зручну інтеграцію з різними сервісами. Для роботи з даними буде застосовуватися JPA/Hibernate, що дозволить ефективно керувати сутностями, будувати складні запити та підтримувати цілісність інформації у базі даних, наприклад PostgreSQL.
     Клієнтська частина веб-версії системи буде реалізована за допомогою React, що дозволить створити динамічний, швидкий та інтуїтивний інтерфейс для операторів курорту й користувачів. Для мобільних спортсменів та інструкторів буде застосовуватися Kotlin із використанням Jetpack Compose, що дозволяє створювати сучасний та зручний мобільний застосунок для Android. Розробка вестиметься у середовищі IntelliJ IDEA та Android Studio, а контроль версій забезпечуватиметься через Git із використанням. Такий набір інструментів гарантує надійність системи, можливість легкого розширення та комфортний процес розробки.
